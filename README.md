# LanShare

LanShare 是面向 Android 手机、Android TV 和电脑浏览器的局域网文件传输工具。设备通过局域网发现并直接传输文件，不依赖云端中转服务。

## 功能

- 自动发现附近设备，并向已知地址发送单播查询，帮助在广播受限的网络中重新发现设备。
- 显示当前 IPv4 网段，手机与 Web 点击复制，TV 使用遥控器确认键复制；设置中支持多个发现网段，在广播受限或跨网段时通过 UDP 查询发现设备。
- 手机、TV 与电脑之间发送和接收文件，接收前可接受或拒绝。
- 查看已接收文件、下载电脑端文件、打开文件位置；TV 接收 APK 后可调用系统安装器。
- 支持中文、空格和其他 Unicode 文件名，对不安全的文件名字符进行过滤。
- 可选诊断日志；日志关闭不影响正常发现和传输。

## 平台与安装

| 平台 | 标识 | 最低系统 / 运行环境 |
| --- | --- | --- |
| Android 手机 | `phone` | Android 8.0（API 26） |
| 旧版 Android TV | `tvLegacy` | Android 5.0（API 21） |
| 新版 Android TV | `tvModern` | Android 8.0（API 26） |
| 电脑浏览器 | Web Desktop | Node.js 18+ 和现代浏览器 |

Android APK 从 [GitHub Releases](https://github.com/meatRoll/lan-share/releases) 下载，按平台选择对应资产；每个平台使用独立发布标签，如 `phone-v1.0.0`。Legacy 与 Modern TV 使用不同的应用 ID。系统满足最低版本不代表所有厂商的存储、文件管理器和安装器行为都已验证。

从 debug 测试版切换到正式签名版时，可能需要卸载后重新安装。卸载前备份需要保留的设置与私有文件。

## 快速使用

### 手机与 TV

1. 安装对应平台的 APK，将设备连接到能够相互访问的局域网。
2. 在发送端和接收端打开 LanShare，等待设备发现；必要时重新搜索。
3. 选择目标设备和文件，在接收端确认接收，等待传输和保存完成。
4. 在已接收文件列表中查看文件或打开位置。Android/TV 默认公共接收目录为 `Download/LanShare`，不可写时可能使用应用存储回退路径。

APK 安装由 Android 系统安装器处理，仍受系统安全策略约束。

### 电脑浏览器

在仓库根目录执行：

```sh
node web/bridge.js
```

打开 <http://127.0.0.1:45880>，保持 Node.js 进程和浏览器页面运行。选择已发现的手机或 TV 后即可选择或拖入文件发送；手机或 TV 向电脑发送文件时，在浏览器中确认接收。

电脑端默认保存到 `~/Downloads/LanShare`。“打开位置”目前使用 macOS 的 Finder 命令，其他系统可直接打开接收目录。环境变量、诊断及运行限制见 [Web Desktop 文档](web/README.md)。无需安装 npm 依赖，不能只打开 `web/index.html` 代替本地服务。

## 网络与安全

请仅在可信局域网中使用。当前发现和传输协议没有设备身份认证或 TLS 加密；接收确认不等于身份认证，不要将服务端口转发到公网。

| 协议 / 端口 | 用途 |
| --- | --- |
| UDP `45454` | Android/TV 与电脑的设备发现 |
| TCP `45455` | Android/TV 文件接收 |
| TCP `45888` | Android/TV HTTP 文件接口，供电脑端代理调用 |
| TCP `45881` | 电脑文件接收，默认监听所有 IPv4 接口 |
| HTTP `127.0.0.1:45880` | 电脑端浏览器界面与本地 API，仅监听回环地址 |

发现不到设备时，先保持双方应用运行，检查防火墙、VPN、访客网络和 AP 隔离。连接同一 Wi-Fi 名称不一定代表设备可以互访。跨网段或广播隔离时，在“设置 → 配置发现网段”（Web 为“设置 → 发现网段”）填写目标所在的 IPv4 CIDR，每行一个，例如 `192.168.1.0/24`、`192.168.2.0/24`。支持 `/20`～`/32` 的私有地址范围，合计最多 4096 个地址；输入会规范化并合并重复或包含的网段。保存后立即分批发送 UDP `QUERY`，每轮完成后等待 30 秒再次查询；已发现且位于配置网段中的地址继续每 3 秒查询。留空停止配置网段搜索，保留原有广播及当前网段已知地址查询。跨网段仍需路由和防火墙允许 UDP `45454` 与传输端口互通；TCP 探测只用于诊断，不是发现兜底。
